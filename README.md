# وصله — Vasleh

نرم‌افزار ماژولار همه‌کاره با **PHP خالص**، بدون فریم‌ورک و بدون بیلد — طراحی‌شده برای **هاست اشتراکی**.

> نسخه برنامه: **۸٫۲٫۱۸** با ۱۹ ماژول فعال — قابل مشاهده روی [atroweb.ir](https://atroweb.ir) (اعمال روی لایو با به‌روزرسانی یک‌کلیکه از پنل ادمین)
> کد منبع: [github.com/farsmd/vasleh](https://github.com/farsmd/vasleh)

## معرفی خلاصه

وصله در یک سیستم، وب‌سایت و وبلاگ، فروشگاه، انبار، تولید و حسابداری را با هم دارد و پنل مدیریتش کاملاً فارسی و راست‌چین است. برای کسب‌وکارهای کوچکی ساخته شده که می‌خواهند از فروش در اینستاگرام به سایت مستقل برسند، یا فروشگاه و تولیدی کوچکی دارند که می‌خواهند مسیر سفارش تا حسابداری را در یک جا ببینند — بدون اینکه سرور اختصاصی بگیرند یا درگیر نگهداری یک استک پیچیده شوند.

ایده مرکزی وصله ساده است: **هر چیزی یک ماژول است.** هسته هیچ ماژولی را نمی‌شناسد؛ پوشه ماژول تازه که به `modules/` اضافه شود، خودش کشف و لود می‌شود و برای نصب شدن به هیچ تغییری در هسته نیاز ندارد. حتی زیرساخت‌ها — نشست، دیتابیس، پنل ادمین، به‌روزرسانی — خودشان ماژول‌اند.

## اصول طراحی

- **فقط PHP.** بدون فریم‌ورک، بدون Composer، بدون Node و بدون مرحله بیلد. کپی فایل‌ها روی هاست یعنی نصب.
- **هاست اشتراکی.** دیتابیس SQLite با PDO، بدون نیاز به MySQL و بدون سرویس جانبی.
- **ماژولار واقعی.** اضافه و کم کردن قابلیت، هسته را دست نمی‌زند.
- **امنیت از ابتدا.** ماژول خراب سیستم را پایین نمی‌آورد؛ دسترسی فایل حصاربندی‌شده است؛ توکن‌ها فقط به‌صورت هش ذخیره می‌شوند.
- **بدون CDN خارجی.** همه فایل‌های شخص ثالث (Bootstrap راست‌چین، CodeMirror، فونت) به‌صورت محلی از داخل برنامه سرو می‌شوند.
- **فارسی و راست‌چین.** پنل ادمین، قالب‌ها و تاریخ‌ها (شمسی با رقم فارسی در کنار میلادی) برای کاربر ایرانی ساخته شده‌اند.

## امکانات

### فروشگاه (`shop`)

- محصول با فیلدهای سفارشی، ویژگی و واریانت با قیمت، موجودی و SKU جدا
- دسته‌بندی درختی، سبد خرید نشستی، تسویه با کد سفارش `VSL-######` و کاهش خودکار موجودی
- پیگیری سفارش با کد و موبایل، فهرست قیمت عمومی و مدیریتی با ویرایش سریع قیمت
- فاکتور چاپی، تنظیمات ارسال، آستانه ارسال رایگان و مالیات

### انبار (`inventory`)

- چندانباره، کالا با SKU یکتا، واحد دلخواه و مقدار اعشاری واقعی
- آستانه هشدار کمبود، اتصال اختیاری به محصول فروشگاه
- سند ورود، خروج و اصلاح با مرجع و موجودیِ بعد از سند، انتقال بین انبارها، کاردکس
- سرویس `inventory.stock` برای استفاده بقیه ماژول‌ها

### تولید (`production`)

- فرمول ساخت (BOM) با اقلام ثبت‌شده در لحظه سفارش (تغییر بعدی فرمول، سفارش‌های قبلی را عوض نمی‌کند)
- سفارش تولید با کد `PRD-####` و کنترل کسری مواد پیش از شروع
- شروع: مواد کم می‌شود؛ پایان: محصول به انبار اضافه می‌شود و موجودی فروشگاه مرتبط بالا می‌رود؛ لغو: مواد برمی‌گردد
- وابسته به ماژول انبار است

### حسابداری (`accounting`)

- حساب‌های مالی با موجودی اول دوره، دسته‌های درآمد و هزینه (فروش، خرید مواد، اجاره، حقوق، حمل‌ونقل، سایر)
- تراکنش با طرف حساب و مرجع، انتقال با کنترل موجودی
- گزارش ماهانه و به‌تفکیک دسته
- واردکردن یک‌کلیکه و بدون تکرار سفارش‌های پرداخت‌شده فروشگاه به‌عنوان فروش (`SHOP-<code>`)

### مدیریت محتوا (`cms`)

- نوشته و صفحه، وبلاگ در `/blog`، چیدمان‌های قابل‌ساخت با جای‌گذار، منوها (یک سطح زیرمنو)
- تنظیمات سایت و صفحه خانه در `/` (روت خانه فقط وقتی ثبت می‌شود که تنظیم شده باشد)
- CSS سراسری در `/cms.css` با نسخه‌بندی بر اساس هش، به‌علاوه CSS هر چیدمان
- «صفحه بدون قالب» (`bare`): بدنه دقیقاً همان‌طور که نوشته شده، بدون هدر و فوتر و قالب و CSS سایت نشان داده می‌شود و در فهرست، نشان «(بدون قالب)» می‌گیرد
- صفحات خطای سفارشی (`/admin/cms/errors`): برای هر کد وضعیت (۴۰۴، ۴۰۳، ۵۰۰ و کدهای دیگر، حتی کد دلخواه) عنوان و بدنه HTML؛ از راه هوک کلی `error_response` در هسته، پاسخ خطای HTML بیرون از پنل ادمین و API با همان کد وضعیت جایگزین می‌شود (۴۰۴ واقعاً ۴۰۴ می‌ماند)؛ صفحه غیرفعال یا حذف‌شده به پیش‌فرض برمی‌گردد
- غیرفعال کردن ماژول، فرانت و پنل محتوا را با هم برمی‌دارد

### پشتیبان‌گیری (`backup`)

- فقط برای مالک سیستم؛ بک‌آپ کامل، دیتابیس یا سفارشی به‌صورت ZIP با مانیفست
- بک‌آپ دیتابیس فقط از روی تصویر لحظه‌ای (`VACUUM INTO`) گرفته می‌شود؛ فایل خام دیتابیس و فایل‌های `-wal` و `-shm` و `-journal` هرگز بک‌آپ نمی‌شوند
- بازیابی از فهرست یا آپلود، با بک‌آپ ایمنی پیش از بازیابی و جایگزینی اتمی
- بک‌آپ دوره‌ای خودکار با هوک `before_dispatch` و قفل فایل

### گزارش‌ها (`reports`)

- ثبت رویدادهای سیستم، کاربر و بازدید با IP، مرورگر و ارجاع‌دهنده، همراه آمار و هرس خودکار
- صفحه‌های فقط‌مالک: گزارش‌ها، کاربران، بازدیدها

### استخراج قیمت (`priceextract`)

- منبع قیمت با نگاشت فیلدهای JSON-API یا آداپتر جدول HTML
- تاریخچه اجرا، فهرست اقلام با فیلتر دسته و جست‌وجو
- واردکردن از CSV برای سایت‌هایی که API عمومی ندارند

### مدیریت شخصی (`personal`)

- در مسیر `/me` با پوسته موبایل‌محور و CSS درون‌خطی (بدون وابستگی استاتیک)
- کارها با موعد اختیاری، رویدادها با تاریخ و ساعت شروع و پایان، نمای روز و هفته (از دوشنبه)
- یادداشت و پروژه با شرح، تاریخ شروع، ساعت لازم و چک‌لیست نیازها با شمارش انجام‌شده‌ها
- حریم خصوصی: هر رکورد مال صاحبش است و هر پرسمان بر اساس مالک فیلتر می‌شود
- اشتراک‌گذاری پروژه و یادداشت به دو روش: با کاربر دیگر سیستم (فقط‌خواندنی و قابل لغو) یا با لینک عمومی فقط‌خواندنی (`/me/share/{token}`) که ساخت لینک تازه، لینک قبلی را باطل می‌کند؛ کارها و رویدادها همیشه خصوصی‌اند
- تاریخ‌ها هم شمسی (با رقم فارسی) و هم میلادی نشان داده می‌شوند؛ ورودی‌های تاریخ، تقویم بومی مرورگر (میلادی) می‌مانند

### دسترسی API (`api`)

- توکن Bearer با پیشوند `vsl_`، ساخت و لغو فقط برای مالک، نمایش متن توکن فقط یک بار در لحظه ساخت
- توکن‌ها فقط به‌صورت هش SHA-256 در `api_tokens` ذخیره می‌شوند
- عملیات فایل با حصار پوشه برنامه (فرار از مسیر رد می‌شود) و پرسمان دیتابیس از API
- روی هاست‌های LiteSpeed، هدر Authorization با قانون `.htaccess` به PHP می‌رسد
- بستن کامل API با غیرفعال کردن همین ماژول از «مدیریت ماژول‌ها» ممکن است (کلید قطع اضطراری)

### پنل ادمین (`admin`)

- منوی آکاردئونی گروه‌بندی‌شده بر اساس ماژول، با آیکون SVG اختصاصی هر ماژول و حفظ حالت باز در localStorage
- سایدبار شیشه‌ای تیره (دسکتاپ ثابت، موبایل کشویی از راست)، هدر شیشه‌ای با جستجوی منو (Ctrl+K) و سوییچ تاریک/روشن، کارت‌های شیشه‌ای نیمه‌شفاف با blur
- داشبورد ویجتی با داده واقعی: زنجیره زنده سفارش، تاگل ماژول‌ها، دلتای واقعی نسبت به دوره قبل، نمودار درآمد/هزینه، کارهای امروز و جدول آخرین سفارش‌ها
- قالب ادمین (`/admin/theme`، فقط مالک): رنگ اصلی، رنگ پنل‌ها در هر دو تم، رنگ پس‌زمینه در هر دو تم، گردی کارت‌ها، اندازه پایه فونت و تم پیش‌فرض — همه واقعاً روی پنل‌ها، کارت‌ها و پس‌زمینه اعمال می‌شوند (نه فقط ذخیره)
- تم یکپارچه: همان متغیرهای قالب ادمین با یک تابع مشترک روی لندینگ، فروشگاه، بخش شخصی و CSS کلی سایت هم می‌نشیند؛ حالت تاریک/روشن با همان کلید localStorage ادمین دنبال می‌شود. CSS سفارشیِ از قبل ذخیره‌شده در `site_css` دست نمی‌خورد (فقط متغیرها اول آن قرار می‌گیرند) و استایل پیش‌فرض نصب‌های تازه با متغیرها نوشته شده است
- ترتیب منو (`/admin/menu`): جابه‌جایی گروه‌ها و آیتم‌ها با درگ‌انددراپ (آیتم فقط داخل گروه خودش) و دکمه‌های بالا/پایین؛ گروه‌ها جمع‌شونده‌اند (حالت باز در localStorage می‌ماند) تا جابه‌جایی گروه‌ها با کارت‌های بلند، سخت نشود
- داده نمونه (`/admin/demo`، فقط مالک): سناریوی کامل و به‌هم‌پیوسته برای تست واقعی — انبار و کالا با موجودی اول دوره، فرمول و دستور تولید برنامه‌ریزی‌شده، دسته و محصول فروشگاه با دو سفارش، حساب‌ها با تراکنش و انتقال؛ همه ردیف‌ها «(نمونه)» دارند و شناسه‌شان در `storage/demo-data.json` ثبت می‌شود، پس «پاک‌سازی» دقیقاً همان‌ها را حذف می‌کند و به داده واقعی دست نمی‌زند (اگر روی ردیف نمونه داده واقعی سوار شده باشد، آن انبار یا حساب می‌ماند و دلیلش گفته می‌شود)
- هدر چسبان موبایل: در نمای باریک، هدر ادمین با ارتفاع داینامیک ویوپورت (`100dvh` تا نوار ابزار مرورگر موبایل صفحه را نلغزاند) و موقعیت چسبان، همیشه بالای صفحه می‌ماند و زیر منوی کشویی قرار می‌گیرد
- فهرست‌ها به سبک کارت‌های مدیریت ماژول‌ها: داشبورد، حساب‌های پولی، توکن‌های API، محتوا، منابع استخراج قیمت و جدول‌های دیتابیس — هر ردیف یک کارت با نشان وضعیت و دکمه‌های همان ردیف است، نه جدول
- ویرایشگر فایل CodeMirror 5.65 (محلی): ذخیره با Ctrl+S، سقف ۵۱۲ کیلوبایت، ذخیره اتمی، پشتیبان خودکار پیش از هر ذخیره با بازیابی یک‌کلیکه، و ثبت همه ویرایش‌ها
- نصب ماژول فقط برای مالک از `/admin/modules/install` (قوانینش پایین‌تر آمده)

## معماری و نوع کدنویسی

### زبان، وابستگی‌ها و سبک

- **PHP نسخه ۸٫۱ به بالا**، بدون فریم‌ورک، بدون Composer، بدون Node و بدون مرحله بیلد.
- **دیتابیس SQLite با PDO** (ماژول `sqlite` سرویس `db` را می‌دهد)؛ هر ماژول جدول‌های خودش را با مایگریشن خودش می‌سازد.
- **فرانت‌اند:** Bootstrap 5.3 راست‌چین و CodeMirror 5.65، هر دو به‌صورت محلی از `assets/` سرو می‌شوند؛ آیکون‌ها SVG درون‌خطی‌اند، نه ایموجی و نه فونت آیکون خارجی.
- **تایپ سخت‌گیرانه:** تمام فایل‌های منطق (هسته و کلاس‌های ماژول) با `declare(strict_types=1)` شروع می‌شوند؛ فقط فایل‌های نمایشی (views) این اعلان را ندارند.
- **کامنت‌های فارسی** در سراسر کد؛ قراردادها و چرایی تصمیم‌ها داخل خود کد نوشته شده، نه در سندی جدا.
- **بدون `mbstring`:** هاست هدف این اکستنشن را ندارد، پس کد از توابع `mb_*` پرهیز می‌کند.
- **بدون وضعیت سراسری پنهان:** وابستگی‌ها از طریق کانتینر سرویس تزریق می‌شوند، نه متغیرهای سراسری.

### ساختار پوشه‌ها

```
index.php        فقط درخواست‌ها را جمع می‌کند و به هسته می‌دهد
core/            هسته: Kernel ،Router ،Container ،ModuleLoader ،Request ،Response ،View ،helpers
modules/         ماژول‌ها؛ نام هر پوشه = slug ماژول، هر ماژول یک core.php دارد
assets/          فایل‌های استاتیک محلی (Bootstrap راست‌چین، CodeMirror و …)
storage/         دیتابیس و فایل‌های زمان اجرا — از وب بسته است
version.json     نسخه سه‌بخشی: {"core":8,"system":2,"other":18} یعنی ۸٫۲٫۱۸
```

### چرخه یک درخواست

```
index.php
  → core/bootstrap.php (اتولودر + helpers)
  → Kernel::handle(Request::capture())
      ۱) ModuleLoader ماژول‌های فعال را از روی پوشه‌ها و
         storage/modules-state.json و modules-meta.json می‌خواند
      ۲) سرویس‌های هر ماژول در Container ثبت می‌شوند
      ۳) مایگریشن هر ماژول اجرا می‌شود؛ خطای یک ماژول فقط
         خودش را کنار می‌گذارد: خطا ثبت و سرویس‌هایش از
         کانتینر حذف می‌شوند تا کسی صدایشان نزند
      ۴) روت‌ها و هوک‌های ماژول‌های سالم جمع می‌شوند
      ۵) درخواست به ماژول مرتبط سپرده و Response برگردانده می‌شود
```

### اتولودر (بدون Composer)

```php
Core\X           => core/X.php
Modules\<Name>\X => modules/<strtolower(name)>/src/X.php
```

نام ماژول فقط با `/^[a-z][a-z0-9_-]*$/` قبول می‌شود؛ پس slug ماژول، نام namespace و نام پوشه باید یکی باشند.

### قرارداد یک ماژول: فایل `core.php`

هر ماژول با یک فایل `core.php` خودش را معرفی می‌کند که یک آرایه برمی‌گرداند:

```php
return [
    'slug'        => 'personal',          // هم‌نام پوشه و namespace
    'title'       => 'مدیریت شخصی',
    'icon'        => '<svg …>…</svg>',    // آیکون SVG درون‌خطی
    'description' => '…',
    'version'     => '1.0.0',
    'system'      => false,               // true یعنی ماژول سیستمی
    'requires'    => ['sqlite', 'session'],

    'services' => [
        // شناسه سرویس => کارخانه‌ای که با Container ساخته می‌شود
        'personal.store' => static fn (Container $c): Personal =>
            new Personal($c->get('db')),
    ],

    'permissions' => [
        'personal.use' => 'استفاده از مدیریت شخصی',
    ],

    'migrate' => static function (Container $c): void {
        $c->get('personal.store')->migrate();
    },

    'admin_menu' => [
        ['label' => 'مدیریت شخصی', 'path' => '/me',
         'permission' => 'personal.use'],
    ],

    'routes' => static function (Router $router, Container $c, string $module): void {
        $router->get('/me', [MeController::class, 'tasks'], $module);
        $router->post('/me/todos', [MeController::class, 'todoCreate'], $module);
        // پارامتر مسیر: /me/todos/{id}/toggle
    },
];
```

نکته‌های قرارداد:

- **سرویس‌ها** با شناسه رشته‌ای در `Container` ثبت می‌شوند (`set`/`get`/`remove`) و کارخانه‌ها تنبل‌اند: تا کسی سرویس را نخواهد، ساخته نمی‌شود.
- **مایگریشن** با هر درخواست اجرا می‌شود ولی ایدempotent است (جدول اگر باشد ساخته نمی‌شود)؛ پس نصب ماژول یعنی فقط اضافه کردن پوشه.
- **دسترسی‌ها** (`permissions`) در پنل، به نقش‌ها وصل می‌شوند و منو و روت بر اساس همان‌ها فیلتر می‌شوند.
- **هوک‌ها** (مثل `before_dispatch`) اجازه می‌دهند ماژولی مثل پشتیبان‌گیری، بدون تغییر هسته، در چرخه درخواست قلاب شود.
- **امنیت روت‌ها:** همه POSTهای `/admin` توکن CSRF (`_csrf`) می‌خواهند؛ ماژول‌هایی که بیرون `/admin` روت دارند (مثل `/me` و فروشگاه)، خودشان ورود و CSRF را کنترل می‌کنند، چون هوک نشست فقط `/admin` را نگه می‌دارد. از ۵٫۸٫۲۰، همه POSTهای تغییرکننده فروشگاه (افزودن و به‌روزرسانی و حذف از سبد، و ثبت سفارش) هم توکن می‌خواهند؛ پیگیری سفارش فقط خواندنی است و توکن نمی‌خواهد.
- **کش مایگریشن (۶٫۹٫۰):** نسخه مایگریشن‌شده هر ماژول در `storage/migrations.json` ثبت می‌شود و مایگریشن فقط با نصب تازه یا تغییر نسخه آن ماژول اجرا می‌شود؛ در حالت پایدار، دیگر ۱۶ ماژول در هر درخواست مایگریشن نمی‌شوند. فقط موفقیت ثبت می‌شود تا مایگریشن ناموفق، درخواست بعد دوباره تلاش شود. این فایل فقط کش است و هرگز در پوش، همگام‌سازی یا زیپ انتشار نمی‌آید (وگرنه نصب تازه با جدول‌های نساخته، مایگریشن را رد می‌کند).
- **خطای ماژول، خطای سیستم نیست:** لودر خطای `core.php` را می‌گیرد و هسته خطای هر ماژول را در مرحله خودش می‌گیرد؛ ماژول خطادار در فهرست می‌ماند ولی سرویس‌هایش حذف می‌شوند.

### نسخه‌بندی و به‌روزرسانی

نسخه سه‌بخشی است و در `version.json` ریشه نگه داشته می‌شود: **هسته . ماژول‌های سیستمی . بقیه**.

- تغییر در `core/` و فایل‌های ریشه → عدد اول
- تغییر در ماژول‌های سیستمی → عدد دوم
- هر تغییر دیگر → عدد سوم

از پنل مدیریت ← «آپدیت» می‌شود نسخه روی گیت‌هاب را دید و با یک کلیک نصب کرد. آپدیتر پیش از نصب در `storage/backups/` بک‌آپ می‌گیرد، به `storage/` (دیتابیس و کلید) دست نمی‌زند، حذف فایل‌ها را فقط طبق مانیفست انجام می‌دهد و با قفل فایل (flock) از اجرای هم‌زمان جلوگیری می‌کند.

### تست و انتشار

هر انتشار با تست‌های خودکار محلی (تست واحد ماژول‌ها و تست سرتاسری HTTP) و ممیزی زنده در برابر گیت‌هاب همراه است: فایل‌های نسخه زنده بایت‌به‌بایت با همان نسخه روی گیت‌هاب مقایسه می‌شوند. انتشار نهایی از روی ZIP آماده انجام می‌شود که بوت آن تست شده است.

## نصب و اجرا

### نیازمندی‌ها

- PHP نسخه ۸٫۱ یا بالاتر با اکستنشن `pdo_sqlite`
- وب‌سرور Apache یا LiteSpeed با mod_rewrite، یا nginx با قوانین معادل پایین

### قدم‌ها

۱) فایل `vasleh.zip` را در ریشه دامنه یا ساب‌دامین از حالت فشرده خارج کنید.
۲) مطمئن شوید پوشه `storage/` قابل نوشتن است (معمولاً 775).
۳) آدرس سایت را باز کنید — دیتابیس و کاربر اولیه خودکار ساخته می‌شوند.
۴) با `admin` / `admin123` وارد شوید و همان لحظه از «حساب کاربری ← تغییر کلمه عبور» رمز را عوض کنید.
۵) برای اتصال راه‌دور: از «دسترسی API» یک توکن بسازید.

اجرای توسعه روی ماشین خودتان:

```bash
php -S localhost:8000
```

### اگر وب‌سرور nginx است

فایل `.htaccess` روی nginx خوانده نمی‌شود؛ این قوانین معادل را در کانفیگ سایت بگذارید:

```nginx
location ^~ /core/    { deny all; }
location ^~ /modules/ { deny all; }
location ^~ /storage/ { deny all; }
location / {
    try_files $uri $uri/ /index.php?$query_string;
}
```

روی Apache و LiteSpeed، همان `.htaccess` همراه برنامه این کارها را می‌کند: دسترسی مستقیم به `core/` و `modules/` و `storage/` را می‌بندد و هدر Authorization را (که بعضی هاست‌ها پیش‌فرض عبور نمی‌دهند) به PHP می‌رساند.

### امنیت بعد از نصب

- رمز اولیه را حتماً عوض کنید (قدم ۴ بالا).
- فایل‌های `storage/database.sqlite` و `storage/app.key` (کلید امضای نشست) هرگز نباید از وب در دسترس باشند و هرگز نباید وارد گیت شوند (در `.gitignore` هستند).
- برای بستن کامل API، ماژول «دسترسی API» را از «مدیریت ماژول‌ها» غیرفعال کنید.

## ساخت ماژول جدید

۱) پوشه‌ای به نام slug ماژول در `modules/` بسازید (فقط حروف کوچک لاتین، عدد، `_` و `-`).
۲) فایل `core.php` را با قرارداد بالا بنویسید و کلاس‌ها را در `src/` با namespace ‏`Modules\<Name>` بگذارید.
۳) پوشه را که اضافه کنید، هسته در درخواست بعدی خودش آن را کشف می‌کند؛ مایگریشن جدول‌ها را می‌سازد و روت‌ها و منو بالا می‌آیند.

### نصب ماژول از پنل (نصب‌کننده ZIP)

- فقط مالک سیستم، از `/admin/modules/install`
- ZIP باید دقیقاً **یک پوشه ریشه** داشته باشد که نامش با slug ماژول یکی باشد و `core.php` داخل همان پوشه باشد
- فرار از مسیر (traversal) رد می‌شود، سقف حجم دارد، نام slug باید با پوشه بخورد، و روی ماژول موجود بازنویسی نمی‌شود
- نصب در گزارش‌ها ثبت می‌شود

ترتیب امن دیپلوی که از یک حادثه واقعی درس گرفته شده: **اول فایل‌های کلاس و ویو، آخر `core.php`** — چون `core.php` همان لحظه‌ای که خوانده شود، کلاس‌هایش را می‌خواهد.
